# The dev box, measured -- 2026-09-06

`CLAUDE.md` describes a **different machine** from the one this repo is now checked out on.
Its toolchain section names `C:\Users\Hoel\.dotnet\dotnet.exe --list-sdks # 9.0.317, 10.0.400`.
That user profile does not exist here. Everything below was measured on the current box
(user `Jonasty`) and should be trusted over `CLAUDE.md` for toolchain facts.

## .NET SDKs -- there is no .NET 10

```
C:\Program Files\dotnet\dotnet.exe --list-sdks      # 6.0.428, 8.0.424      <- first on PATH
C:\Users\Jonasty\AppData\Local\Microsoft\dotnet\dotnet.exe --list-sdks   # 9.0.317 only
C:\Users\Jonasty\.dotnet\                            # caches only, no sdk\ folder
C:\Users\Jonasty\.dotnet-sdk8\dotnet.exe             # an 8.x
```

A recursive search for any `dotnet` SDK directory matching `10.0.*` returns nothing, and
`shared\Microsoft.NETCore.App` tops out at `9.0.19`.

**Consequence.** Every `net10.0` project in this repo -- all five `*.Server`, all four
`*.Game`, all eight test projects, `tools/Blackjack.Console` and `tools/Poker.Console`:
**19 of the 25 `.csproj` in the tree** -- dies on NETSDK1045 before compiling a line.
`dotnet build SPT-Casino.slnx` cannot succeed here until either a .NET 10 SDK is installed
or the tree is retargeted.

The 9.0.317 SDK being present and .NET 10 being absent is not neutral: **net9.0 is exactly
what the SPT 4.0.x line targets**, and net10.0 is what 4.1.0 moved to. This box is
provisioned for the 4.0.x world.

`CLAUDE.md`'s advice to "put that directory ahead of `C:\Program Files\dotnet` on PATH"
still applies, but it buys net9.0 here, not net10.0.

The `.Client` projects are `net472` and are unaffected by all of this.

The EFT build `0.16.9.40087` is the one the work order names for 4.0.13, so the client and
server halves agree.

Layout worth knowing: the server lives under `C:\SPT\SPT\`, server mods under
`C:\SPT\SPT_Runtime\user\mods\`, plugins under `C:\SPT\BepInEx\plugins\`.

**This is a live, heavily-modded install, not a test rig.** ~45 plugin folders including
SAIN, Waypoints, DynamicMaps, MoxoPixel.MenuOverhaul, a backported Icebreaker map whose
README is written for "SPT 4.0.x" and for Fika co-op, and Fika itself. Treat it as
read-only unless installing the casino into it is the explicit task.

Only one server mod is installed: `WTT-ServerCommonLib`.

## Why this matters to the work order

The work order frames the choice as 4.0.13-with-old-Fika versus moving to 4.1.x. The box
says the user is **already living on the 4.0.13 + Fika 2.3.5 combination**, with a large mod
set built for it. Moving to 4.1.x is not a fresh start there -- it is abandoning a working
install. That belongs in the decision, and it was not in the work order's framing.

See `2026-09-06-phase0-verification.md`.
